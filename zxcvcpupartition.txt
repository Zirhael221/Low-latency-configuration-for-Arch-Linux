# zxcv.cpu.partition 

A hardcore, kernel-level tuning utility designed to eliminate micro-stutters, bypass hardware interrupts, and minimize jitters for gaming on Linux. 

Built specifically for modern Arch/CachyOS systems, this script reaches deep into the Linux scheduler, memory manager, and I/O subsystems.
You MUST disable conflicting user-space tuning daemons before using this script. If you leave these running, they will actively fight the script and cause massive stuttering.
Run this in your terminal:
`sudo systemctl disable --now ananicy-cpp irqbalance tuned`
Please disable anyother performance tuning app or services installed than may conflict with this script!

---

## 🛑 Why Feral GameMode and Custom Schedulers are Obsolete Here

* **Feral GameMode / gamemoderun:** GameMode is just a user-space wrapper. All it does is tell the OS to change the CPU governor to `performance`, change the I/O scheduler, and apply a standard `renice` priority to the game. **This script already does all of this at the root kernel level.** Furthermore, because we launch the game with `chrt -r 50` (Real-Time priority), we completely override and outrank anything GameMode could ever do. Using GameMode alongside this script will just cause them to fight each other.
* **Custom CPU Schedulers (BORE, EEVDF, Cachy):** The job of a CPU scheduler is to fairly divide CPU time between hundreds of fighting threads. Because our script uses `chrt` (Real-Time Round-Robin) and strict CPU isolation, **we bypass the fair scheduler entirely**. When a thread is marked Real-Time, the standard scheduler throws its hands up and just gives the core to the game infinitely. The scheduler algorithm literally doesn't matter anymore. However the housekeeping cores still follow the scheduler so if you have any application that benefits from using a custom scheduler please let me know and i can figure out a way for it to work.

## 🚀 Features & What It Does

### 1. CPU Core Isolation & Thread Management 
* **What it does:** Dedicates specific cores purely for gaming, while forcing the OS, background apps, and drivers onto "Housekeeping" cores.
* **Isolation Rule:** Do not isolate too many cores. Only isolate the minimum amount of cores required to achieve your target FPS or performance to prevent OS thread starvation.

### 2. GPU & Direct Memory Access (IOMMU)
* **What it does:** Completely disables kernel virtualization security checks (`iommu=off`) for absolute bare-metal hardware speed, and locks PCIe lanes to max power (`pcie_aspm.policy=performance`).
* **Why it matters:** The CPU stops auditing memory requests. Your GPU, NVMe drive, and Network Interface can read/write directly to physical RAM without translation overhead, heavily reducing input lag. Optimus laptops also get NVIDIA DRM modesetting to prevent "Async Page Flip" hard-freezes.

### 3. Memory Locking & Swap Assassination
* **What it does:** Permanently disables physical disk swap, ZRAM, and ZSWAP, while granting all users `mlock` privileges.
* **Why it matters:** Prevents the OS from temporarily moving game assets to your hard drive. Games and Proton can lock their data permanently into high-speed physical RAM, eliminating traversal stutters. (Automatically cleared when the game exits).

### 4. Smart Power States (C-States & P-States)
* **What it does:** Allows you to permanently pin the CPU at max frequency (`idle=poll`), OR use intelligent scaling that prevents deep sleep.
* **Why it matters:** If you opt out of `idle=poll` (recommended for laptops), the script applies `cstate=1` and `pstate=active`. This allows the CPU to scale its clock speed to manage heat, but mathematically forbids the cores from entering deep sleep states (C2/C3), meaning wake-up latency remains at near-zero.

### 5. Network & Sysctl Latency Tweaks
* **What it does:** Edits the kernel's virtual memory and TCP/IP stack rules.
* **Why it matters:** Uses **Busy Polling** (`busy_read=50`) so the CPU actively checks network sockets for new game packets instead of waiting for a hardware interrupt. Tweaks `dirty_ratio` to force the OS to write smaller data chunks in the background, preventing I/O stutters.

## Installation

1. Download the script directly from this repository:

   ```bash
   curl -LO [https://raw.githubusercontent.com/Zirhael221/Low-latency-configuration-for-Arch-Linux/main/zxcvcpupartition.txt](https://raw.githubusercontent.com/Zirhael221/Low-latency-configuration-for-Arch-Linux/main/zxcvcpupartition.txt)

Move it to your local binaries and rename it:

   sudo mv zxcvcpupartition.txt /usr/local/bin/zxcv.cpu.partition

Make the script executable:

   sudo chmod +x /usr/local/bin/zxcv.cpu.partition

Run:

sudo zxcv.cpu.partition
